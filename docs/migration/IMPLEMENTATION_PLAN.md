# Unified cloud migration implementation and evidence

The approved V2 master prompt is the design and execution authority. One private
GitHub repository holds code and authenticated encrypted backups; one GitHub
Actions writer operates all three lanes; the existing Notion data source holds
operational records. No new hosted database or paid AI service is required.

1. Sync and audit both repositories and all schedulers; verify private destination.
2. Preserve source files, event identities and uncertainty; encrypt and restore-test
   SQLite, both complete logs and additional private workflow state.
3. Extend the existing Notion source additively; fetch all existing paginated bodies;
   compare content and property hashes before any canonical transition.
4. Implement immutable operational records with readback, rate-limit handling,
   conflict routing and explicit uncertain-write reconciliation.
5. Replace routine application approval with evidence-based automatic eligibility;
   use only verified facts and permitted submission adapters with receipts.
6. Deploy 06:00 accepted relationships and 06:30 first touch America/Chicago;
   integrate applications as the second 06:30 phase if no prior cadence exists.
7. Run fixture/unit/security/restore/CI and cloud shadow checks. Keep local actors
   active and cloud writes disabled until all cutover evidence is present.
8. At a single authorized cutover: retire audited local writers, take a final delta,
   confirm Notion reconciliation and enable cloud operation. If a required external
   credential or actor reconciliation is missing, leave activation blocked and
   finish every independent engineering task.

Tasks are split among Notion/storage, application eligibility/submission,
history/archive, and orchestrator/security lanes. The root agent reviews interfaces
and runs the combined verification suite before pushing the migration unit.
